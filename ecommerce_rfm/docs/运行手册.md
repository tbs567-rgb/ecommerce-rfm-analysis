# 项目运行手册

> 项目：《基于 RFM 与 K-means 聚类的电商客户价值分析及交互式可视化》
> 数据：UCI Online Retail，541,909 条交易（2010-12 ~ 2011-12）
> 栈：Hadoop 3.3.6（HDFS）+ Spark 4.3.0 + MySQL 8.0 + Pandas/sklearn/Plotly，全开源正版
>
> **本手册以项目根目录为基准**，所有路径都是相对路径。

## 1. 前置条件

- **数据库**：双击 `0_start_mysql.bat`（内置绿色版 MySQL 8.0.38，端口 **3307**，root/123456）
- **HDFS**：只有跑 Spark 作业 / 答辩演示时才需要，平时关着不影响看板和数据库
- **Python 环境**：项目自带 `python_env\Scripts\python.exe`，不用系统 Python，不用安装任何东西
- **路径要求**：整个文件夹必须放在纯英文路径下（MySQL 8.0 不支持中文路径）

## 2. HDFS 启动 / 验证 / 停止

**启动**：双击 `1_start_hdfs.bat`，等约 30 秒，窗口里出现 `NameNode` 和 `DataNode` 两行即成功。
日志在 `bigdata\logs_nn.out` / `bigdata\logs_dn.out`。

**验证**：

```cmd
bigdata\jdk-11.0.32.1+1\bin\jps.exe
```

**停止**：双击 `9_stop_hdfs.bat`（按 PID 杀进程，`stop-dfs.cmd` 在 Windows 上不可靠）。

**HDFS 命令行**（想手动敲 hdfs 命令时，先加载环境）：

```cmd
bigdata\env.bat
hdfs dfs -ls /ecommerce/raw/        :: 原始数据
hdfs dfs -ls /ecommerce/analysis/   :: Spark 分析产物
```

管理界面：http://localhost:9870

## 3. Spark 作业运行

**冒烟测试**（最常用）：双击 `2_spark_smoketest.bat`，约 25 秒后输出：

```
[SMOKE] HDFS CSV rows = 541909  (expect 541909)

```

**手动提交**：

```cmd
bigdata\spark-4.3.0-bin-hadoop3\bin\spark-submit.cmd file:///绝对路径/ecommerce_rfm/scripts/13_spark_smoketest.py
```

⚠️ 脚本路径**必须带 `file:///` 前缀**，裸 `D:\xxx.py` 会报 `No FileSystem for scheme "D"`。

## 4. 全链路重跑（从原始数据到最终结果）

数据已在 HDFS / MySQL 里，以下仅在**想从头复现**时使用：

```cmd
:: ① 双击 0_start_mysql.bat 和 1_start_hdfs.bat
:: ② 原始数据上 HDFS（已有文件，重传会覆盖，可跳过）
bigdata\env.bat
hdfs dfs -put -f file:///绝对路径/ecommerce_rfm/data/raw/online_retail_raw.csv /ecommerce/raw/

:: ③ Spark ETL：清洗→统计→RFM→写回 MySQL（约 5~15 分钟）
::    直接双击 3_run_full_etl.bat

:: ④ K-means 聚类 → customer_segments 表
python_env\Scripts\python.exe ecommerce_rfm\scripts\07_kmeans.py

:: ⑤ 重新生成静态看板 HTML
python_env\Scripts\python.exe ecommerce_rfm\scripts\08_dashboard.py
```

跑完核对：③ 末尾七项对账都显示 `OK`；`SELECT COUNT(*) FROM transactions_clean` = 536,641。

## 6. MySQL 常用查询

连接参数：Host `127.0.0.1`，Port **3307**，Database `ecommerce_rfm`，User `root`，Password `123456`。

```cmd
mysql_portable\bin\mysql.exe -h127.0.0.1 -P3307 -uroot -p123456 ecommerce_rfm
```

用图形客户端也可以（DBeaver / Navicat / Workbench 均可，驱动用 `bigdata\jars\mysql-connector-j-8.4.0.jar`）。

**常用 SQL：**

```sql
-- ⚠️ 列名大小写敏感：驼峰列必须写 InvoiceNo，不能写 invoice_no
SELECT COUNT(*) FROM transactions_clean;                            -- 536,641
SELECT COUNT(*) FROM transactions_clean WHERE is_valid_purchase=1;  -- 391,153
SELECT COUNT(*) FROM customer_rfm;                                  -- 4,334
SELECT COUNT(*) FROM customer_segments;                             -- 4,334

-- 三类客户画像
SELECT segment_label, COUNT(*) AS 人数,
       ROUND(AVG(M),0) AS 平均消费,
       ROUND(100*SUM(M)/(SELECT SUM(M) FROM customer_rfm),1) AS 销售额占比
FROM customer_segments GROUP BY segment_label;
```

四张表：`transactions_raw`（原始 54 万行）→ `transactions_clean`（清洗后带标记列）→ `customer_rfm`（RFM 值）→ `customer_segments`（聚类标签）。字段说明见 `ecommerce_rfm\docs\表结构说明.md`。

## 7. 常见问题（FAQ）

| 症状 | 原因 / 解决 |
|---|---|
| `0_start_mysql.bat` 报 `Failed to set datadir` | 文件夹路径含中文，移到纯英文路径下 |
| `spark-submit` 报 `No FileSystem for scheme "D"` | 提交的 .py 路径没加 `file:///` 前缀 |
| SQL 报 `Unknown column 'invoice_no'` | 列名大小写敏感，写驼峰 `InvoiceNo` |
| hdfs 命令卡住无响应 | HDFS 没启动，先双击 `1_start_hdfs.bat` |
| jps 看不到 NameNode | 看 `bigdata\logs_nn.out` 末尾报错；常见原因是 9000 端口被占 |
| exit code 是 0 但事情没做 | Windows cmd 包装脚本退出码不可信，一切以输出和查询结果为准 |
| MySQL 写入报 schema 校验错误 | Spark 4.3 对已存在表校验严格——已用 DROP 自建表方案绕开，勿改回 append |
| 网页报"无法连接 MySQL" | 先双击 `0_start_mysql.bat`，看到 `[OK]` 再启动网页 |

## 8. Streamlit 交互网页（三个页面）

**启动**：双击 `6_open_streamlit.bat`，约 5 秒后浏览器自动打开 http://localhost:8501
（关闭黑窗口即停止服务）。

**三个页面与 12 张图**（课程要求"至少 6 张图、至少 2 张交互图"）：

| 页面 | 图表 | 交互 |
|---|---|---|
| 销售概览 | 月度销售额趋势、商品 Top10、国家分布 | 日期范围、国家多选、明细表导出 |
| 客户价值分析 | 消费金额分布（对数）、帕累托图（前 20% 贡献 74.6%）、R/F/M 三分布 | R/F/M 滑块筛选、客户编号查询、CSV 导出 |
| 客户分群 | 各群人数、销售额贡献、RFM 画像热力图、3D 散点 | 客户群多选、名单导出、群画像与运营建议 |

**数据源**：直连 MySQL `ecommerce_rfm`（端口 3307），口径 `is_valid_purchase=1 AND is_special=0 AND Quantity>0`，页面 KPI 应显示 £8,737,228 / 18,402 单 / 4,334 客户。
