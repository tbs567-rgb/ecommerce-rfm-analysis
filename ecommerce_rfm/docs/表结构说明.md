# MySQL 表结构说明 — ecommerce_rfm

> MySQL 8.0.38 ｜ 库：`ecommerce_rfm`（utf8mb4）｜ 工具链：Python SQLAlchemy + PyMySQL 读写，DBeaver 可视化管理
> 开发顺序：先建原始表和清洗表并导入 → 算完 RFM 写入第三张表 → K-means 聚类完成后写入第四张表

## 表关系

```
transactions_raw ──(清洗去重+打标)──> transactions_clean
                                          │
                            (is_valid_purchase=1 过滤，按 CustomerID 汇总)
                                          ▼
                                    customer_rfm ──(K-means聚类)──> customer_segments
                                                                      (4,334 行，k=3)
```

- `transactions_raw` → `transactions_clean`：同源映射，541,909 行 → 536,641 行（去掉完全重复 5,268 行）
- `transactions_clean.customer_id` = `customer_rfm.customer_id`（1 : 0..1，每位有效客户一行 RFM）
- `customer_rfm.customer_id` = `customer_segments.customer_id`（1 : 0..1，每位客户一个簇标签）

## 1. transactions_raw — 原始交易明细（541,909 行）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AUTO_INCREMENT | 代理主键 |
| invoice_no | VARCHAR(20) | 订单号（C 开头 = 取消单） |
| stock_code | VARCHAR(32) | 商品编码 |
| description | VARCHAR(255) NULL | 品名 |
| quantity | INT | 数量 |
| invoice_date | DATETIME | 交易时间 |
| unit_price | DECIMAL(10,2) | 单价 |
| customer_id | INT NULL | 客户编号（缺失=未知客户） |
| country | VARCHAR(64) | 国家 |

索引：`idx_cust(customer_id)` `idx_date(invoice_date)` `idx_inv(invoice_no)`

## 2. transactions_clean — 清洗后明细 + 标记（536,641 行）

在 raw 字段基础上增加：

| 字段 | 类型 | 说明 |
|---|---|---|
| amount | DECIMAL(12,2) | 交易金额 = Quantity × UnitPrice（退货为负，保留可对账） |
| has_customer | TINYINT | 客户编号非空标记 |
| is_cancelled | TINYINT | 取消单（InvoiceNo 以 C 开头） |
| is_return | TINYINT | 退货/负数量（非取消） |
| is_bad_price | TINYINT | 单价 ≤ 0（盘点调整类） |
| is_special | TINYINT | 邮费/折扣/手工/礼品卡等非商品项 |
| is_valid_purchase | TINYINT | **有效购买口径** = 有客户 & 非取消 & 非退货 & 数量>0 & 单价>0 & 非特殊编码 |
| order_month | CHAR(7) | 交易年月（YYYY-MM，方便聚合） |

索引：同 raw 之外增加 `idx_valid(is_valid_purchase)`

## 3. customer_rfm — 客户 RFM 特征（4,334 行）

| 字段 | 类型 | 说明 |
|---|---|---|
| customer_id | INT PK | 客户编号 |
| R | SMALLINT | 参考日期(2011-12-10，最后交易日次日) − 最近一次有效购买日期（天） |
| F | INT | 有效订单编号去重计数（按订单，不按明细行） |
| M | DECIMAL(12,2) | 有效购买金额求和 |
| last_purchase | DATETIME | 最近有效购买时间 |
| first_purchase | DATETIME | 首次有效购买时间 |

## 4. customer_segments — 分群结果（待 K-means 聚类完成后写入）

计划字段：`customer_id PK`、`cluster INT`、`segment_label VARCHAR(50)`（如 重要价值/重要保持/一般发展/一般挽留）、`clustered_at DATETIME`。

## ⚠️ 2026-11-04 更新：Spark 链路重建了三张核心表

应用户要求引入 Hadoop + Spark 后，`transactions_raw` / `transactions_clean` / `customer_rfm` 三张表**由 PySpark JDBC 重建并写入**（见 `docs/大数据链路说明.md`），与 Pandas 版逐项对账一致。当前表结构差异：

| 项 | 原 Pandas 建表 | 现 Spark 建表 |
|---|---|---|
| id 自增主键 | 有 | 无 |
| 二级索引 | 有（cust/date/inv/valid） | 无（分析量级无影响） |
| 列名大小写 | InvoiceNo 驼峰 | InvoiceNo 驼峰（**本机 MySQL 列名大小写敏感，SQL 必须用驼峰**） |
| 清洗表月份列 | order_month | year_month |
| customer_rfm | 同 | customer_id/R/F/M/last_purchase/first_purchase（同名） |

`customer_segments`（K-means）未受影响，仍为原表。
