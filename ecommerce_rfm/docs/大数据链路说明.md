# 大数据链路说明（Hadoop HDFS + Spark）

> 2026-11-04 新增。在原有 Pandas 单机链路基础上，增加 Hadoop + Spark 分布式链路，两条链路**结果逐项对账一致**。

## 架构

```
原始 Excel → CSV (541,909 行, 45.6MB)
      │
      ▼ hdfs dfs -put
HDFS (Hadoop 3.3.6 伪分布式, NameNode+DataNode 本机, hdfs://localhost:9000)
  /ecommerce/raw/online_retail_raw.csv
      │
      ▼ spark-submit (PySpark 4.3, local 模式, JDK 17)
PySpark ETL (scripts/09_spark_etl.py)
  ├─ 清洗：去重 5,268 → 536,641 行；标记列 has_customer/is_cancelled/is_return/
  │        is_bad_price/is_special/is_valid_purchase；amount=Quantity×UnitPrice
  ├─ 统计：月度趋势 / Top10 商品（结果写回 HDFS /ecommerce/analysis/）
  ├─ RFM：参考日期=2011-12-10，F 按订单去重，M 求和 → 4,334 客户
      │ JDBC (mysql-connector-j 8.4.0, batchsize 10000)
      ▼
MySQL ecommerce_rfm（transactions_raw / transactions_clean / customer_rfm 由 Spark 重建并写入）
      │
      ▼ 与 Pandas 基线对账（7 项）
outputs/spark_check.json → all_ok = true
```

## 注意事项（踩坑记录）

1. **Java 版本分裂**：Hadoop 3.3.6 只支持 Java 8/11；PySpark 4.3 要求 Java 17+。本机两套 JDK 并存：HDFS 守护用 JDK11，spark-submit 用 JDK17（`11_spark_submit.py` 内指定 JAVA_HOME）。
2. **Spark 4.3 JDBC 写已存在的表会报 COLUMN_NOT_DEFINED_IN_TABLE**（append/overwrite+truncate 都触发，Spark 4 的严格 schema 校验问题）→ 采用 **DROP + Spark 自建表**（`createTableColumnTypes` 显式指定类型）绕开。
3. **Spark 自建表的特点**：无 id 自增主键、无二级索引、列名保留驼峰（InvoiceNo）；本机这台 MySQL **列名大小写敏感**（`invoice_no` 查不到，必须 `InvoiceNo`）——写 SQL 注意。
4. hdfs put 本地路径必须 `file:///D:/...` 前缀，裸 `D:\` 路径会被当 HDFS 路径。
5. hdfs.cmd / spark-submit.cmd 的 exit code 不可信（cmd 包装丢失），一切以实际输出/查询结果为准。
6. customer_segments（K-means 结果）仍为 Pandas+sklearn 链路产出，未受本次重建影响；07/08 步读的是 CSV 产物，与 Spark 链路解耦。
7. **独立版 spark-submit 提交 .py 脚本必须用 `file:///D:/...` 前缀**——裸 Windows 路径 `D:\xxx.py` 的 `D:` 会被当 URI scheme，报 `No FileSystem for scheme "D"`。
8. 独立版 Spark 的 `conf/spark-env.cmd` 已配置：JAVA_HOME=jdk-17、HADOOP_HOME/HADOOP_CONF_DIR 指向 Hadoop（使其能直读 hdfs://localhost:9000）、PYSPARK_PYTHON 指向项目 venv。
